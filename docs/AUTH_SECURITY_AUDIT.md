## 1. Executive Summary

The Machinichi authentication system has a **solid foundation** with several enterprise-grade practices already in place. ## 2. Architecture Overview

### Current Auth Flow

```
Frontend                     Backend
────────                     ───────
SignIn.jsx
  POST /api/auth/login   →   loginSchema (Zod) validation
                             Find user by email/phone
                             bcrypt.compare(password)
  ←  { accessToken }         Sign JWT (15min)
                             Set httpOnly refreshToken cookie
  
  localStorage.setItem("accessToken", token)  ← ⚠️ XSS Vulnerable
  sessionStorage.setItem("machinichiSignedIn", "true")  ← ⚠️ Not secure
```

### Token Architecture (Current)
- **Access Token**: JWT, stored in `localStorage` — **XSS vulnerable**.
- **Refresh Token**: Likely httpOnly cookie (backend sets it, good).
- **Admin Access Token**: Stored in `localStorage` as `"adminAccessToken"`.
- **Auth Gate**: `sessionStorage.getItem("machinichiSignedIn") === "true"` — this is not cryptographically secure; anyone can set this in devtools.

### What's Working Well
1. Rate limiting on ALL auth endpoints (strict: 10 req/15min, OTP: 3 req/15min).
2. Zod validation on all request bodies with strict schemas.
3. Helmet.js for security headers.
4. Firebase Admin SDK for Google token verification.
5. Custom NoSQL injection sanitization middleware.
6. User `isBlocked` check in auth middleware.
7. Role-based access control (`role: 'customer' | 'admin'`).
8. Password strength rules enforced on both frontend AND backend.

## 5. Session & Token Security

### 5.1 Critical Issue: Access Token in localStorage

**Current:**
```javascript
// SignIn.jsx
localStorage.setItem("accessToken", res.data.accessToken);
```

**Why this is dangerous:**
- Any JavaScript on the page (including XSS-injected scripts) can read `localStorage`.
- Third-party scripts (analytics, chat widgets) run in the same JS context.
- Browser extensions can read localStorage.

**Recommended Fix — Memory Storage + httpOnly Cookies:**

**Option A (Best): Store access token in memory, refresh token in httpOnly cookie**

```typescript
// Backend: send both tokens as httpOnly cookies
res.cookie('accessToken', accessToken, {
  httpOnly: true,
  secure: process.env.NODE_ENV === 'production',
  sameSite: 'strict',
  maxAge: 15 * 60 * 1000, // 15 minutes
  path: '/',
});

res.cookie('refreshToken', refreshToken, {
  httpOnly: true,
  secure: process.env.NODE_ENV === 'production',
  sameSite: 'strict',
  maxAge: 7 * 24 * 60 * 60 * 1000, // 7 days
  path: '/api/auth/refresh',  // Limit refresh cookie to only the refresh endpoint
});

res.json({ success: true }); // No token in response body
```

```typescript
// Backend: auth middleware reads from cookie instead of Authorization header
export const authenticateUser = async (req, res, next) => {
  const token = req.cookies.accessToken || req.headers.authorization?.split(' ')[1];
  // ...
};
```

```jsx
// Frontend: remove all localStorage.setItem("accessToken") calls
// Auth state determined by calling /api/auth/me endpoint
const checkAuth = async () => {
  try {
    const { data } = await axios.get('/api/auth/me', { withCredentials: true });
    setUser(data.user);
    setIsSignedIn(true);
  } catch {
    setIsSignedIn(false);
  }
};
```

**Option B (Acceptable): Keep access token in memory (React state), NOT localStorage**

```jsx
// In App.jsx
const [accessToken, setAccessToken] = useState(null); // Memory only, NOT localStorage

const completeSignIn = (token) => {
  setAccessToken(token); // Never written to localStorage
  setIsSignedIn(true);
};

// Pass to API calls via axios interceptor
axios.interceptors.request.use((config) => {
  if (accessToken) config.headers.Authorization = `Bearer ${accessToken}`;
  return config;
});
```

### 5.2 sessionStorage Auth Gate Is Not Secure

**Current:**
```javascript
// App.jsx — security check
const [isSignedIn, setIsSignedIn] = useState(
  () => sessionStorage.getItem("machinichiSignedIn") === "true"
);
```

**Problem**: Anyone can open DevTools → Console → `sessionStorage.setItem("machinichiSignedIn", "true")` → refresh page → they're "signed in".

**Fix**: Auth state must be verified by calling the backend (`/api/auth/me` with actual token), not by a flag in storage.

### 5.3 Refresh Token Rotation

**Recommended implementation (backend):**
```typescript
// On /api/auth/refresh endpoint:
router.post('/refresh', async (req, res) => {
  const oldRefreshToken = req.cookies.refreshToken;
  if (!oldRefreshToken) return res.status(401).json({ message: 'No refresh token' });

  try {
    const decoded = jwt.verify(oldRefreshToken, JWT_REFRESH_SECRET);
    
    // Token rotation: invalidate old refresh token
    await RefreshToken.findOneAndDelete({ token: oldRefreshToken, userId: decoded.userId });
    
    // Issue new pair
    const newAccessToken = jwt.sign({ userId: decoded.userId }, JWT_ACCESS_SECRET, { expiresIn: '15m' });
    const newRefreshToken = jwt.sign({ userId: decoded.userId }, JWT_REFRESH_SECRET, { expiresIn: '7d' });
    
    // Store new refresh token hash in DB
    await RefreshToken.create({ userId: decoded.userId, token: newRefreshToken });
    
    res.cookie('accessToken', newAccessToken, { httpOnly: true, secure: true, sameSite: 'strict', maxAge: 15 * 60 * 1000 });
    res.cookie('refreshToken', newRefreshToken, { httpOnly: true, secure: true, sameSite: 'strict', maxAge: 7 * 24 * 60 * 60 * 1000 });
    
    res.json({ success: true });
  } catch {
    res.clearCookie('accessToken');
    res.clearCookie('refreshToken');
    res.status(401).json({ message: 'Invalid refresh token' });
  }
});
```

### 5.4 Cookie Configuration Recommendations

```typescript
// Production cookie settings
const cookieOptions = {
  httpOnly: true,        // ✅ Prevents JavaScript access
  secure: process.env.NODE_ENV === 'production',  // ✅ HTTPS only in prod
  sameSite: 'strict',    // ✅ Prevents CSRF
  domain: process.env.COOKIE_DOMAIN || undefined,
  path: '/',
};
```

### 6.3 Password Reset Security

**Current flow:**
1. User requests reset → email sent with token
2. User clicks link → token in URL → POST `/api/auth/reset-password`

**Issues:**
- Reset token is in URL query parameter (`?token=xxx`) → logged in browser history, server logs, referrer headers.
- No expiry enforcement shown in frontend — backend must enforce (recommended: 30–60 minutes).
- No "invalidate token after use" shown.

**Recommendations:**
```typescript
// In reset-password controller:
const tokenRecord = await PasswordResetToken.findOne({ token: hashedToken });

if (!tokenRecord || tokenRecord.expiresAt < Date.now()) {
  return res.status(400).json({ message: 'Reset link has expired or already been used' });
}

// Invalidate immediately after use:
await PasswordResetToken.deleteOne({ _id: tokenRecord._id });

// Force logout all sessions after password reset:
await RefreshToken.deleteMany({ userId: user._id });
```

### 6.4 Breach Detection

**Recommended — Check HaveIBeenPwned API:**
```typescript
import crypto from 'crypto';

async function isPasswordBreached(password: string): Promise<boolean> {
  const hash = crypto.createHash('sha1').update(password).digest('hex').toUpperCase();
  const prefix = hash.slice(0, 5);
  const suffix = hash.slice(5);

  const res = await fetch(`https://api.pwnedpasswords.com/range/${prefix}`, {
    headers: { 'Add-Padding': 'true' }
  });
  const text = await res.text();
  return text.split('\n').some(line => line.startsWith(suffix));
}

// Use in registration and password change:
if (await isPasswordBreached(password)) {
  return res.status(400).json({
    message: 'This password has appeared in a data breach. Please choose a different one.'
  });
}
```

## 7. OTP & Phone Verification

### 7.1 Current Implementation Review

**Frontend sends:**
```javascript
// CreateAccount.jsx
await axios.post(`${API}/send-otp`, { phone: `${country.dial}${form.phone}`, devMode });
```

**Issues:**

| Issue | Severity | Description |
|-------|----------|-------------|
| `devMode: true` sent to backend | 🔴 Critical | Backend returns OTP in response body when `devMode: true` — this must never reach production |
| OTP returned in API response | 🔴 Critical | `if (res.data.otp) { const digits = res.data.otp.toString().split("") }` — OTP exposed in HTTP response |
| Phone not verified before account use | 🟡 Medium | If OTP step is skipped (UI bypass), account may be created with unverified phone |
| OTP timer only in frontend | 🟡 Medium | Backend must also enforce OTP expiry (5 minutes max) |
| No max OTP attempt limit per phone | 🟡 Medium | 3 OTP sends per 15min but no limit on verify attempts per OTP |

### 7.2 Critical Fix: Remove devMode from Production

```typescript
// backend/src/controllers/auth.controller.ts
export const sendPhoneOTP = async (req: Request, res: Response) => {
  const { phone, devMode } = req.body;

  // NEVER expose OTP in response in production
  const isDevMode = devMode === true && process.env.NODE_ENV !== 'production';

  const otp = generateOTP(); // 6-digit
  await storeOTP(phone, otp, 5 * 60); // expires in 5 minutes

  if (isDevMode) {
    // Only in development
    return res.json({ message: 'OTP sent (dev mode)', otp });
  }

  // Production: send via SMS (MSG91)
  await sendSMS(phone, `Your Machinichi OTP is ${otp}. Valid for 5 minutes. Do not share.`);
  return res.json({ message: 'OTP sent successfully' });
};
```

### 7.3 OTP Best Practices

```typescript
// Secure OTP implementation:

// 1. Use cryptographically secure random OTP
const generateOTP = (): string => {
  return crypto.randomInt(100000, 999999).toString();
};

// 2. Store hashed OTP (not plaintext) in Redis/DB
const hashedOTP = crypto.createHash('sha256').update(otp).digest('hex');
await redis.setex(`otp:${phone}`, 300, hashedOTP); // 5 min TTL

// 3. Verify with rate limit per phone
const attempts = await redis.incr(`otp_attempts:${phone}`);
if (attempts === 1) await redis.expire(`otp_attempts:${phone}`, 900); // 15 min window
if (attempts > 5) {
  return res.status(429).json({ message: 'Too many OTP attempts. Try again in 15 minutes.' });
}

// 4. Verify and delete
const storedHash = await redis.get(`otp:${phone}`);
const inputHash = crypto.createHash('sha256').update(inputOTP).digest('hex');
if (storedHash !== inputHash) {
  return res.status(400).json({ message: 'Invalid OTP' });
}
await redis.del(`otp:${phone}`);
await redis.del(`otp_attempts:${phone}`);
```

## 9. Security Headers & CORS

### 9.1 Current Implementation

**Helmet.js** is configured in `server.ts`:
```typescript
app.use(helmet());
```
Default Helmet includes: `X-DNS-Prefetch-Control`, `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `X-XSS-Protection`, `Strict-Transport-Security`.

**CORS:**
```typescript
app.use(cors({
  origin: process.env.CLIENT_URL || 'http://localhost:5173',
  credentials: true,
}));
```

### 9.2 Issues

| Header | Issue |
|--------|-------|
| CSP | Not configured — Helmet uses default which may be too permissive |
| HSTS | Default Helmet HSTS may not be configured for production domain |
| CORS | Single origin only — no array support for staging/preview URLs |
| Rate Limit Headers | Not shown to user on 429 responses |

### 9.3 Recommended Header Configuration

```typescript
// server.ts — Enhanced security headers

app.use(helmet({
  contentSecurityPolicy: {
    directives: {
      defaultSrc: ["'self'"],
      scriptSrc: ["'self'", "https://apis.google.com", "https://www.gstatic.com", "https://hcaptcha.com"],
      styleSrc: ["'self'", "'unsafe-inline'", "https://fonts.googleapis.com"],
      fontSrc: ["'self'", "https://fonts.gstatic.com"],
      imgSrc: ["'self'", "data:", "https://images.unsplash.com", "https://flagcdn.com", "https://lh3.googleusercontent.com"],
      connectSrc: ["'self'", process.env.CLIENT_URL || "http://localhost:5173"],
      frameSrc: ["'none'"],
      objectSrc: ["'none'"],
      upgradeInsecureRequests: process.env.NODE_ENV === 'production' ? [] : null,
    },
  },
  hsts: {
    maxAge: 31536000, // 1 year
    includeSubDomains: true,
    preload: true,
  },
  referrerPolicy: { policy: 'strict-origin-when-cross-origin' },
  crossOriginEmbedderPolicy: false, // Required for Firebase
}));

// Enhanced CORS
const allowedOrigins = [
  process.env.CLIENT_URL,
  'https://machinichi.com',
  'https://www.machinichi.com',
  ...(process.env.NODE_ENV !== 'production' ? ['http://localhost:5173'] : []),
].filter(Boolean);

app.use(cors({
  origin: (origin, callback) => {
    if (!origin || allowedOrigins.includes(origin)) {
      callback(null, true);
    } else {
      callback(new Error('CORS: Origin not allowed'));
    }
  },
  credentials: true,
  methods: ['GET', 'POST', 'PUT', 'PATCH', 'DELETE'],
  allowedHeaders: ['Content-Type', 'Authorization'],
}));
```

### 10.1 Hardcoded API URLs

**Found in multiple files:**
```javascript

const API = "http://localhost:5000/api/auth";
```

**Fix — use environment variables:**
```javascript
// .env (frontend)
VITE_API_BASE_URL=http://localhost:5000/api

// In code (create src/lib/api.js):
import axios from 'axios';

const api = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  withCredentials: true,
  timeout: 10000,
});

// Request interceptor — attach token
api.interceptors.request.use((config) => {
  const token = localStorage.getItem('accessToken'); // Move to memory after security fix
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

// Response interceptor — auto refresh
api.interceptors.response.use(
  (response) => response,
  async (error) => {
    if (error.response?.status === 401 && !error.config._retry) {
      error.config._retry = true;
      try {
        await axios.post(`${import.meta.env.VITE_API_BASE_URL}/auth/refresh`, {}, { withCredentials: true });
        return api(error.config);
      } catch {
        window.location.href = '/signin';
      }
    }
    return Promise.reject(error);
  }
);

export default api;
```

### 12.5 GDPR / DPDPA Compliance (India)

For a global platform with Indian users:

1. **Cookie consent banner** before setting any non-essential cookies.
2. **Privacy policy** must describe data collected, stored, used.
3. **Data export**: `GET /api/user/export-data` → download all personal data as JSON/PDF.
4. **Account deletion**: `DELETE /api/user/account` → hard delete or anonymize all user data.
5. **Data retention policy**: Define how long order data, logs are retained.

```typescript
router.delete('/user/account', authenticateUser, async (req, res) => {
  const { password } = req.body;
  // Verify password before deletion
  const isValid = await bcrypt.compare(password, req.user.password);
```
